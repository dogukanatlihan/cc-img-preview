# cc-img Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code mod that draws a clickable thumbnail in the terminal transcript for every image Claude reads, makes, receives from a tool or is given in a prompt, and opens the image in the OS default app.

**Architecture:** One hooks module wires engine events to small pure modules. A `tool.call` hook queues work; a timer drains the queue, runs an OS helper process to produce a tiny BMP (and a PNG in pixel terminals), and stores the thumbnail in session state keyed by row. `ui.render` hooks draw the stored thumbnails as rows of plain `Button`s (block mode) or an `Image` (pixel mode).

**Tech Stack:** Claude Code mod API (`claude-code` types, TSX with the global `h`), Windows PowerShell + `System.Drawing`, `sips`, optional `ffmpeg` / ImageMagick / `rsvg-convert`. Tests with `claude-code/testing` through `claude plugin test`.

**Spec:** `C:\Users\me\cc-img\docs\superpowers\specs\2026-11-17-cc-img-design.md`

## Global Constraints

- Mod name `cc-img`, version `0.1.0`.
- `MOD` in this plan is `C:\Users\me\.claude\dev-mods\<session>\cc-img`. The engine hot-reloads it at the end of each turn. The first file written there makes Claude Code ask the person "Turn on the mods Claude writes in this session?".

If that folder is gone, load the `plugin-authoring` skill again and use the path it prints.
- A hooks module has no Node and no DOM. Everything outside goes through `$`. Sibling `.ts`/`.tsx` files in the mod may be imported.
- The mod never changes, delays or fails a tool call, and adds nothing Claude can read. Every `tool.call` hook returns exactly what `await next(e)` gave it.
- Terminal surface only: every render hook returns `next(e)` unchanged when `e.surface !== 'terminal'`.
- Spec values, verbatim: thumbnail box at most 40 columns by 16 rows; at most 4 images per call; thumbnail data kept for the 40 most recent images; temp folders deleted after 7 days; helper timeout 5 seconds; PNG thumbnail about 480 pixels wide and under 2 MiB.
- Image extensions: png, jpg, jpeg, gif, bmp, webp, svg, tif, tiff, avif, ico.
- Processes are started only as argument vectors through `$.process.run`, never as a shell string built from a path.
- No git commits unless the person asks. Each task ends by running the checks below, not by committing.
- Checks, run from any folder: `claude plugin validate "MOD"`, `claude plugin test "MOD"`, and `npx -y -p typescript tsc -p "MOD"` once the engine has laid `MOD/.claude-plugin/types/`.

## Review Focus

Each line names a condition no task's happy-path test covers; its test lives in the task named.

1. File names with spaces, brackets, non-ASCII letters or Windows backslashes (`C:\Users\me\my shot (1).png`) are found, thumbnailed and opened. Task 2 and Task 4.
2. A huge or slow image (helper still running after 5 seconds) leaves the row with its caption only and never blocks the queue. Task 5.
3. A file that is not really an image (zero bytes, or text named `.png`) gives a caption with no picture, and no error line. Task 5.
4. Text that only looks like an image path (`https://x.dev/a.png`, a file name in prose that does not exist, a file that exists but was not changed by the call) produces no thumbnail. Task 2 and Task 6.
5. State stored by an earlier version of the mod, or a click on an image that has since been deleted, does not break drawing: old state is declined by its `shape` tag and the click gives a toast. Task 7 and Task 8.

### Task 7: Store, queue and collection wiring

**Files:**
- Modify: `MOD/types/index.d.ts`, `MOD/hooks/register.tsx`
- Test: `MOD/hooks/register.test.tsx`

**Interfaces:**
- Consumes: `collect` (Task 6), `detectEnv`, `makeThumb`, `saveBase64` (Task 5), `parseBmp`, `fitBox` (Task 3), `baseName` (Task 2).
- Produces, in `types/index.d.ts`:
  ```ts
  export type Thumb = {
    openPath: string; name: string
    width: number; height: number        // original, 0 when unknown
    columns: number; rows: number        // 0 and 0 when there is no picture
    rgb?: string                         // base64, columns * pxH * 3 bytes; block mode
    pxH?: number
    png?: string                         // base64 PNG; pixel mode
  }
  export type RowThumbs = { images: Thumb[] }
  export type Recent = { rowId: string; openPath: string }[]   // newest last
  export type Mode = 'block' | 'pixel'
  ```
  with a `PluginState['cc-img']` entry holding a family `rows` of `RowThumbs` keyed by row id, `recent: Shaped<Recent>` and `mode: Shaped<Mode>`.
